# 模块详解（compositor-retouch）

[SKILL.md](../SKILL.md) 的展开版，按小节查：依赖与输入、图层文件夹、各模块的算法与参数、`--refresh`、图形界面、检查图、须知。命令配方和预设表在 SKILL.md 里。

## 依赖与输入

- 依赖：
  - `python3 -m pip install "opencv-python-headless<5" pillow numpy`
  - 可选：`python3 -m pip install ai-edge-litert`（只是 TFLite 推理库，不带 OpenCV）。装了以后，皮肤蒙版用 Google 的人像多类别分割模型（MediaPipe，Apache 2.0）区分头发、皮肤和衣服，比按纹理判断准得多（浅色刘海、垂下的发丝、皱纹明显的皮肤）。模型 16 MB，第一次用时从 Google 的模型存储下载到 `~/Library/Caches/compositor-retouch/`，按 SHA-256 校验。没装、下载失败或加 `--no-parsing` 时退回纹理判断，脚本会提示。不要装 `mediapipe` 整包：它会带上 OpenCV 5，和上面的 OpenCV 4 冲突。
  - 人脸关键点和人像分割用 Apple Vision，需要 macOS（人像分割要 macOS 12 以上）和 Xcode Command Line Tools 里的 `swiftc`（没有就运行 `xcode-select --install`）。脚本第一次运行时把 `scripts/face_landmarks.swift` 编译到 `~/Library/Caches/compositor-retouch/`，之后直接复用，全程是命令行，没有窗口。
  - 拿不到 Vision 时退回 OpenCV 找人脸：没有关键点，眼神光、骨相的蒙版改为黑色（需手涂），皮肤蒙版不再按人像范围限定。OpenCV 5 去掉了 Haar 人脸检测，这时连人脸都找不到，磨皮退回按分辨率估算。脚本都会给出警告。

输入支持 JPEG、PNG、TIFF，包括 16 位、EXIF 方向和嵌入的 ICC（自动转为 sRGB）。HEIC 或 RAW 要先转换，例如 `sips -s format tiff in.heic --out in.tif`。

16 位的照片（16 位 TIFF、PNG，浮点 TIFF）新建工程时保留 16 位：原图是 16 位图层，工程是格式 12，**要 Compositor 1.5 以上才能打开**。旋转方向和色彩配置文件交给苹果的 ImageIO、ColorSync 处理，和 Compositor 自己导入时一样（用的是人脸识别那个小工具，同样需要 `swiftc`；没有时退回 8 位并警告）。高低频的两层也跟着是 16 位，合起来就是原图；磨皮层直接在原图（或 16 位的高低频）之上时也是 16 位，从 16 位原图算出，图层名标"16 位"，重做、重算后仍是 16 位，所以在皮肤上做很重的调色也不会先在磨皮层上出断层；磨皮之下还有别的层时按 8 位画面算，图层也是 8 位。其他自动修饰的层是 8 位，在各自的蒙版范围内以 8 位精度盖在原图上。给旧版 Compositor 用时加 `--8bit`，照旧做成 8 位、格式 11 的工程。

已有工程可以是 Compositor 1.5、1.6 存的（工程格式 12 到 21）：里面的 16 位图层和 HDR（OpenEXR）图层按 Compositor 显示的样子读成 8 位来计算（HDR 高光截到白），原图层不动，格式版本保持不变；新加的图层都是 8 位。用户自己加的减少杂色（Reduce Noise，格式 21）调整层原样保留，但计算新图层和渲染时不重现它，脚本会提示。

## 图层文件夹

新图层按用途放进文件夹，自下而上：

| 文件夹 | 里面是 |
|---|---|
| 🎚️ 高低频 | `--freq-sep` 的低频、高频，紧贴原图 |
| 🧴 皮肤 | `--delicious-skin` 的磨皮层，在高低频之上 |
| 🌓 光影 | `--sculpt`、`--neutral-gray`、`--dual-curves`（双曲线的提亮、压暗两层） |
| 😊 五官 | `--eyes` |
| 🎬 调色 · 风格名 | `--look`，每种调色单独一个文件夹，文件夹不透明度就是强度 |
| 🌟 辉光 | `--glow` 的各层（双色辉光是带蒙版的子文件夹） |
| 胶片颗粒、观察组 | 不放文件夹，始终在最上面（观察组在最顶） |

- Compositor 的文件夹是穿透的：分组不改变画面（测试里逐像素核对过），里面的调整层照样作用于下面的全部内容。关掉文件夹的眼睛就是这一类修饰的修前对比；文件夹的不透明度会乘到里面每一层上，可以整体减弱。
- 已有同类文件夹时，新层放进它的最上面；没有时按上表的顺序新建在合适的位置。文件夹和图层都靠名字开头的 emoji 识别，改名时保留 emoji 即可（手动磨皮层保留开头的 🔥✋，它标记"手动"）；磨皮、眼神光改名后照样被认出来重做、重算。光影、五官、辉光挪进用户自己的文件夹也认得出来；高低频、皮肤两个要留在原图正上方，挪走后再加皮肤模块会另建一个。
- 以前版本生成的工程（图层没有分文件夹，或带有去瑕疵、去油光、肤色统一、淡化法令纹、牙齿、黑眼圈、背景等已去掉的模块）照样能追加：旧图层原地不动，新文件夹按上表插在同类旧图层的上方。
- 新层要放进的文件夹被用户隐藏了时，照样放进去，但会警告"加上了但看不见"。

## 模块

原图正上方是"皮肤层组"：高低频在「🎚️ 高低频」文件夹里，磨皮在「🧴 皮肤」文件夹里，按这个顺序叠放；每一层都基于它下方的实际效果计算：

| 参数 | 生成内容 | 图层类型 · 混合模式 | 用户接下来做什么 |
|---|---|---|---|
| `--freq-sep` | 低频 + 高频，放在原图正上方的「🎚️ 高低频」文件夹里。半径按最大那张脸的宽度取 1/200（最少 1.5 像素），所以大头照、半身照、合影分出来的都一样：毛孔、细纹、小瑕疵在高频，肤色、色块和脸部明暗在低频。没找到人脸时按分辨率；`--blur-radius` 可手动指定。低频图层名写着半径和取法（"按脸宽""按分辨率""手动"）。原图是 16 位时两层也是 16 位 | 像素 · Normal / Linear Light | 低频上修色块（模糊、涂抹工具），高频上修瑕疵（仿制图章默认只取当前图层，正合适）。两层合起来就是原图（误差不超过 1 级）。上面的磨皮层是快照，会盖住在这里手修的地方（磨皮 88% 时只透出 12%）：手修完保存后运行 `--refresh`（见下文） |
| `--delicious-skin` | DR5 磨皮（默认 `form` 引擎，"保形"）：先把找得到的痘印、小暗斑、小红点修掉（用周围的肤色填平，再从旁边干净的皮肤移植纹理，不是模糊；装了人像分割模型时搜整张脸，每张脸找到 10 处以上时判为痘痘肌，再把"稍暗又稍红"的痘印也算上），图层名标"祛痘 N 处"；然后导向滤波只平滑粗频，细纹理（毛孔）取自原图；统计只看皮肤本身，所以睫毛、鼻孔、嘴唇、头发的暗色不会渗进旁边的皮肤；眼、鼻孔、嘴周围放轻，保留五官的立体阴影；另外淡化圆形的暗斑，而线条（法令纹、轮廓）、高光和耳朵不动。配面部锁定、去掉头发和五官的羽化蒙版 | 像素 · Normal 88% | 调不透明度；检查、修补蒙版；想保留的痣在高频上用仿制图章盖回，再 `--refresh` |
| `--delicious-skin manual` | 同上，但是**手动磨皮**：图层带黑蒙版，像 DR5 的手动磨皮一样，用白画笔刷在想磨的地方。磨皮算到人物全身的皮肤（脖子、手、肩膀，头发和衣服除外），所以刷到哪里都有效；没有皮肤的地方就是原图，刷到也不会出怪东西 | 像素 · Normal 88% · 黑蒙版 | 白画笔刷出要磨的区域，低流量可以分层刷 |

其余图层按用途放进上面的文件夹（观察组之下）。"预涂"表示有关键点时蒙版已经按五官涂好，没有关键点时是黑蒙版：

| 参数 | 生成内容 | 图层类型 · 混合模式 · 蒙版 | 用户接下来做什么 |
|---|---|---|---|
| `--sculpt` | 3D 骨相：Compositor 的 Tonal Contrast 调整层，**实时**，半径按脸宽（脸宽的 1/12），强度 40；格式 18 以前的工程改用中频反差像素层 | 调整层 · Normal · 预涂鼻梁、颧骨、眉骨、下巴（半强度）<br>旧格式：像素 · Soft Light 60% | 白画笔加强、黑画笔收回；双击改强度、半径 |

| `--grain` | 胶片颗粒，尺寸随分辨率 | Grain 调整层 | 双击调整强度、尺寸 |
| `--inspection` | 两个观察组，都是默认隐藏的文件夹，曲线按观察组下方实际画出的画面（含已有的调色）校准：<br>黑白 + 反差：Photoshop 默认权重的黑白，再用一条以这张脸的黑白亮度为中灰、周围反差 ×2 的曲线，白皙和深肤色的脸都能看清明暗斑驳；做中性灰、双曲线时打开<br>颜色：先把亮度拉平，再用红绿蓝通道曲线把这张脸的平均肤色变成灰、和它不同的颜色放大 3 倍：正常的皮肤是灰的，泛红是红的，眼下发青是蓝的；暗斑这类只差亮度的看不出来，要看黑白那组。之后再加调色，整体会偏一个颜色，需要时删掉这两个文件夹重新加 `--inspection`，它会按现在的画面重新校准。已有的观察组不重复建 | 调整层文件夹 | 打开其中一个文件夹的眼睛检查，交付前关闭（两个都打开时上面那个盖住下面的） |

辉光颜色（`--glow 风格:颜色`）：

| 名称 | 颜色 | 说明 |
|---|---|---|
| `natural` | 原色 | 光本身的颜色：暖灯发暖光，天空发蓝光。颜色叠加关闭（白色），打开就能换色 |
| `white` | 白 `#FFFFFF` | |
| `gold` | 暖金 `#FFD08A` | 夕阳、暖调人像 |
| `film` | 胶片橙红 `#FF994E` | `halation` 的默认值 |
| `red` | 红 `#FF5A40` | 更浓的胶片红晕 |
| `rose` | 玫瑰粉 `#FF8FB8` | |
| `lavender` | 薰衣草紫 `#B8A0FF` | 冷色 |
| `ice` | 冰蓝 `#9CCBFF` | 冷色 |
| `teal` | 青 `#6FE3D6` | 冷色 |
| `#RRGGBB` | 任意颜色 | 例如 `mist:#FFB070` |

- 颜色放在图层的"颜色叠加"效果里，用户在 Compositor 里随时可以换，不用重新生成。滤色只会加亮：深色（如暗红）的光晕很弱，颜色主要出现在高光周围，接近纯白的高光本身不会变色。
- 冷色（绿、青、蓝、紫）照到脸上会显得发青、气色差。用了冷色且找到人脸时，白蒙版在皮肤处自动减到 40%，图层名会注明；要恢复，在蒙版上用白画笔涂回。
- `dream` 不能加颜色：它是调整层，Compositor 不给调整层画效果。想要彩色的雾感，用 `mist:颜色`。

其他参数：
- `--skin-strength 0.1–2`：磨皮自己的力度：不透明度（1 时 88%，0.6 时 53%，1.15 以上 100%）和它先行祛痘的灵敏度。不是 1 时，磨皮的图层名里会记下（"力度 0.7"），`--refresh` 重算时照用。皮肤本来就好时用 0.5–0.7。痘痘肌不用调高：祛痘会自动按痘痘肌加强；修完还看得见痘印再试 1.2，再往上会开始修掉雀斑和毛孔。没给时磨皮跟着 `--strength`。
- `--strength 0.1–2`（默认 1）：辉光的不透明度和调色文件夹的不透明度；没给 `--skin-strength` 时也管磨皮。
- `--texture natural|soft|smooth`（默认 `natural`）：磨皮保留多少细纹理，即原图细节和磨皮的分界（脸宽的 1/150、1/200、1/260，最少 1.5 像素）。和 Photoshop 的 DR5 插件（反相高反差：高反差 fw/60、亮光、100%）比，本工具用 88% 不透明度，分界不受 1.5 像素下限影响时：`natural` 保留 93% 的毛孔纹理、淡掉 53% 画上的痘印（DR5：88%、56%）；`soft` 85%、60%，质感接近 DR5，痘印去得更多；`smooth` 78%、64%，更精致。三档在五官旁边的改动都只有 DR5 的约三分之二，也没有 DR5 鼻翼边的橙色描边。脸宽不到约 400 像素时，`soft` 和 `smooth` 因为下限几乎一样。正常观看尺寸下 `natural` 88% 和 DR5 100% 干净程度相当，差别只在细纹理的软硬。
- `--engine form|guided|bilateral`：磨皮引擎，默认 `form`（保形，见上表）。`guided` 是之前的引擎（RGB 三通道各做导向滤波，统计包括非皮肤），`bilateral` 是双边滤波。在 6 张 NASA 肖像上画的痘印和真实的法令纹、眼袋上测（`tests/bench.py smoothing`），满强度时 `form` 比 `guided`：淡掉的痘印 60% 对 51%，法令纹和眼袋的形状多保留约 6 个百分点，五官旁皮肤的亮度改动少 22%、颜色偏移少 24%，毛孔纹理相同；24MP 上速度相当。
- `--blur-radius N`：高低频半径（像素），默认是最大那张脸宽度的 1/200，最少 1.5；没找到人脸时按分辨率。
- `--no-vision`：不用 Apple Vision，改用 OpenCV 找人脸（没有关键点）。Vision 结果异常时用。
- `--no-parsing`：不用人像分割模型，按纹理区分头发和皮肤。
- `--force`：配合 `--init` 替换已有工程。
- `--8bit`：配合 `--init`，只写 1.5 以前的 Compositor 读得懂的内容：16 位的照片也做成 8 位图层，骨相、眼神光用像素层，工程是格式 11。
- `--no-checks`：不生成检查图。
- `--render [文件]`：把整个工程按 Compositor 导出的方式合成成一张 JPEG 或 PNG（默认 `<名称>.render.jpg`）。可以单独用（只读工程，不改动），也可以和其他模块一起用（先加图层再渲染）。之后用 Read 工具看这张图，就能确认最终效果，不需要打开 Compositor。
- `--refresh`：手修之后按工程现在的样子重算磨皮层（以及旧格式工程里的眼神光像素层），不加新图层，见下文。实时的骨相、眼神光调整层本来就跟着下面变，不需要重算。
- `--without 模块`：从预设里去掉某个模块，可以重复，例如 `--preset dr5 --without grain --without sculpt`。
- `--progress`：每开始一步打印一行 `[STEP] 2/7 delicious_skin`，渲染和检查图前各打印 `[STEP] render`、`[STEP] checks`。给图形界面显示进度用。

## 手修之后重算（`--refresh`）

磨皮层（以及格式 19 以前的工程里的眼神光像素层）是按生成时它们下方的画面算出来的像素快照，在各自蒙版范围内盖住下面的内容。之后在它们下面手修（高频上用仿制图章修纹理、低频上匀色，或者直接修原图），修过的地方会被盖住，比如磨皮 88% 时只透出 12%。这时运行 `--refresh`：

- 从下往上，每层按它下方现在实际画出来的样子重算像素。图层 id、名字、蒙版、不透明度、位置都不变，只换像素，所以用户擦改过的蒙版都保留（手动磨皮刷出的范围也保留），Compositor 里选中的图层也不变。
- 力度用图层名里记下的（"力度 0.7"），没记就是 1（或这次给的 `--strength`）；磨皮的引擎和质感也按图层名。
- 不动的：用户直接在上面画的层（中性灰）、所有调整层（双曲线的蒙版可能涂过；实时的骨相、眼神光本来就跟着下面变）、旧格式的 3D 骨相像素层（柔光，不盖住下面）、辉光（要更新就删掉重新生成），以及以前版本做的去瑕疵、去油光、肤色统一、淡化法令纹层。
- 脚本只读得到磁盘上的工程。**先让用户在 Compositor 里 ⌘S 保存**，否则重算用的是保存前的内容，而且 Compositor 会问要用磁盘上的版本还是保留自己的。
- 和其他模块一起给时先重算，新加的层基于重算后的结果。没有可重算的层时提示并跳过。新像素先写到工程包里的隐藏文件夹 `.retouch/`，校验通过后一起原子替换；中途失败全部还原。
- 没改过下面时重算，画面几乎不变（测试里平均 0.01 级，只有个别修过的斑借到的纹理不同）。

## 图形界面

`app/` 里是这个脚本的 macOS 图形界面「Compositor 工具」（SwiftUI）。它会自动认出 Compositor 正在编辑的工程（需要一次辅助功能权限），点一下就能精修，修完 Compositor 自动载入新图层；还可以缩成浮在 Compositor 上的悬浮球，点开选功能再精修。也可以把一批照片拖进去，点选预设、模块、调色和辉光，批量生成工程。这些都不用和 AI 对话。它调用的就是这个文件夹里的 `retouch_builder.py`，改了脚本不用重新编译。第一次启动时，它会联网装一个自己的 Python 环境。用 `app/build.sh` 编译，打包成这个文件夹里的 `Compositor 工具.dmg`（打开后是拖到「应用程序」的安装窗口），脚本本身不安装到任何地方；用 `app/Tests/run.sh` 测试，说明见 [app/README.md](app/README.md)。

app 自带编译好的 Apple Vision 人脸组件和分割模型，通过环境变量 `RETOUCH_VISION_HELPER`、`RETOUCH_PARSING_MODEL` 交给脚本，第一次运行不用现场编译和下载。

用户想点按钮操作、不想打命令时，告诉他们这个 app。不要替用户启动它，也不要打开访达。

## 须知

- 像素层是按"它下方 Compositor 实际画出来的结果"计算的快照。用户在 Compositor 里手工改过下方的像素后，这些层不会跟着变；用 `--refresh` 按现在的画面重算（见上文）。调整层（双曲线、颗粒、观察组、调色，格式 18/19 起的骨相、眼神光）是实时的。
- 工程格式版本：新建工程的版本跟着内容走，含骨相是 18、含眼神光是 19（2026-10 以后的 Compositor 1.5.x 才能打开），否则 11（16 位照片 12）；`--8bit` 固定 11 并改用像素层。已有工程保持它的版本，低于 18/19 时骨相、眼神光仍是像素层，脚本会说明；Compositor 每次保存都写它最新的格式（1.5.x 是 20，1.6 起是 21），所以在那里 ⌘S 一次再加就是实时层。app 每次精修前先保存，从 app 来的工程直接得到实时层。实时层的效果和像素版对过（骨相在三张测试照上对面部结构的改动是像素版的 0.9–1.0 倍，细纹理多提亮约 7%，像素版约 4%）。
- 磨皮需要检测到人脸才能按脸宽取参数、先行祛痘；没检测到时按分辨率平滑整片肤色区域并警告。歪头、多人合影也能处理，每张脸各自计算。
- 磨皮先行祛痘的阈值是用人工点在一张真实肖像上的斑调出来的：明显的痘印、暗斑基本都能修掉，很淡的痕迹会放过（默认偏保守）。在那张满脸雀斑的测试照上，默认强度只修了 3 处，大部分雀斑没动。痣如果在尺寸范围内也会被修，要保留就在高频层上用仿制图章盖回，再 `--refresh`，或改用 `--delicious-skin manual` 避开它。
- 皮肤蒙版：肤色范围之外，还从这张脸自己的两颊和额头学习肤色，所以背光一侧的皮肤、深肤色在阴影里都能覆盖；有人像分割时只在人物身上取。头发、衣服由分割模型排除（模型在每张脸周围裁一块来看，头发边缘更细）；胡子仍按"纹理加颜色"排除。没有模型时头发靠纹理密度排除，眼睛以下还要求颜色不像皮肤，浅色刘海会漏进来一部分、额头偶尔有一小块被误判成头发。在 6 张不同肤色的肖像上，下半张脸的覆盖率都在 98% 以上。模型自己的说明里写着它在最深的肤色（Monk 9–10 档）上准确度明显偏低，请看 `masks.jpg`。
- 五官有关键点时按实际轮廓避让，没有时按人脸框比例避让；鼻翼沟、皱纹这类线状结构按形状排除（只修圆形的斑）。脸的上下方向按 Vision 的左右眼标签和嘴的位置定，躺拍、头转过 90° 的脸，骨相、取肤色的位置也不会画反。这些都是近似，侧脸、遮挡、很小的脸可能不准，请看检查图。
- 辉光不进任何预设，因为它是风格，不是修饰，用户要时再加。它放在「🌟 辉光」文件夹里、胶片颗粒之下（颗粒应该在光晕上面），无论两者哪个先加；后加的辉光在先加的上面。`mist`、`halation` 是按下方像素层算出的快照：哪里发光、多亮是固定的，之后在下面加了调色，光晕不会跟着变，需要时重新生成；颜色可以随时改。下方的调整层都会计入（例如用户自己加的全局曲线），但之后再加或修改调整层，辉光不会跟着变。`dream` 是实时的。
- 带颜色叠加的图层，Compositor 在画布上按最长边不超过 1536 像素预览效果，放大到 100% 时光晕会比导出的略软，导出是全分辨率。原色（叠加关闭）没有这个问题。不认识图层效果的旧版 Compositor 会忽略颜色叠加，显示原色光晕。
- 渲染和所有"按下方效果计算"的图层，用的是同一套合成：像素层的全部混合模式、蒙版、文件夹蒙版和不透明度、颜色叠加，以及曲线、色阶、曝光、色相/饱和度、色彩平衡、黑白、渐变映射、颗粒、反相、高斯模糊这些调整层。调整层的算法逐行移植自 Compositor 的源码，测试里和它的原代码逐像素对比，最大差 1 级。没有复现的有：动感模糊、添加杂色、颜色叠加以外的图层效果（描边、投影、发光）、剪贴蒙版、旋转或翻转的图层。遇到这些时脚本会给出警告，渲染里没有它们的效果。颜色加深/减淡、亮光等几种由 Core Image 实现的混合模式用的是标准公式，没有和 Compositor 逐像素核对过。
- 调色是全图的，皮肤也跟着变。`cool-fair`（冷白皮）会明显提亮、冷却肤色，在深肤色上尤其明显，请看 `look.jpg`，必要时降低文件夹不透明度，或在文件夹上加蒙版避开皮肤。
- 皮肤层组是原图正上方的「🎚️ 高低频」「🧴 皮肤」两个文件夹（以前版本的工程里是原图上方名字以低频、高频、🩹、🔥、🌗、〰️、💧、🎨 开头的散图层），文件夹和图层都靠名字开头识别。用户改名后不影响工程有效，只会影响以后新层插入的位置。
- 高低频和磨皮一起用（`dr5` 预设）时：磨皮层是按当时画面算出的快照，在皮肤蒙版内以 88% 盖在高低频上面。在高低频上手修完，保存后运行 `--refresh`，磨皮层就按修过的画面重算；否则手修的地方大部分被盖住。
- 重复运行不会堆第二套图层：高低频、中性灰、3D 骨相、实时的眼神光、胶片颗粒、同一种调色、观察组已存在时跳过（输出 `[SKIP]`），双曲线只补缺的那一层；磨皮（以及旧格式的眼神光像素层）已存在时按这次的参数原地重做（输出 `~ … (重做 · 保留蒙版)`），图层 id、蒙版、位置不变，所以改了力度、质感、引擎再跑一次就生效，手动刷出的蒙版也保留。自动蒙版和手动刷出算两种磨皮层（手动的名字以 🔥✋ 开头），各留一层；要换一种，先删掉旧的。只有辉光会叠加（后加的在上面）。`--refresh` 则是按图层名里记下的旧参数重算。
- 写入顺序：所有新 PNG 先写在包内的隐藏文件夹 `.retouch/`（`images/` 之外，Compositor 看不到变化），按 Compositor 的加载规则（含本机内存预算）校验 manifest，删除过期的 `QuickLook/` 预览，最后几毫秒内把文件 rename 进 `images/` 并原子替换 `manifest.json`，Compositor 只重载一次（它每次重载都要重新解码所有图层，陆续写入会让它反复重载、退避等待）。任何一步失败都会撤销本次写入的文件。运行期间工程若被 Compositor 保存过（用户按了 ⌘S），脚本不会用旧的 manifest 覆盖它：报错退出、不改动工程，再跑一次即可（app 会自动再跑一次）。
- 修改脚本后运行 `tests/run.sh`（说明见 [tests/README.md](tests/README.md)）：全程命令行，包括按 Compositor 加载规则的校验和各模块的量化测试。
