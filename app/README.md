# Compositor 工具.app

`retouch_builder.py` 的 macOS 图形界面，用 SwiftUI 写，需要 macOS 26（Liquid Glass）。所有修图都由 skill 的脚本完成，app 只做三件事：把界面上的选择拼成命令行参数，按队列一张张运行，再把脚本的输出显示成进度、结果和检查图。工具栏中间的「Compositor | PhotoCraft」切换修给哪个编辑器：PhotoCraft 标签页运行 `photocraft-retouch/scripts/pcraft_retouch.py`（见下文）。

## 使用

双击 skill 文件夹里的 `Compositor 工具.dmg`，会出现安装窗口：把左边的「Compositor 工具」拖到右边的「应用程序」就装好了。也可以不装，直接在窗口里双击运行。

- **PhotoCraft 标签页**：工具栏中间切到「PhotoCraft」，照片会做成 PhotoCraft 的 `.pcraft` 文档（同样的预设、模块、调色和辉光，右边的设置两个标签页共用），拖入已有的 `.pcraft` 会追加图层。图层由同一个 `retouch_builder.py` 计算，再由 PhotoCraft 的命令行引擎 `photocraft-cli serve` 搭进文档，全程没有窗口；第一次用时脚本自动下载这个引擎（0.19.0，约 107 MB，按 SHA-256 和 Apple 公证校验后缓存在 `~/Library/Caches/photocraft-retouch/`），侧栏的 PhotoCraft 卡片显示它是否已就绪。
  - 每个标签页有自己的队列：照片按加入时所在的标签页处理，`.comp` 总是 Compositor 的，`.pcraft` 总是 PhotoCraft 的；拖入的全是另一个编辑器的文档时，窗口自动切到那个标签页。「开始精修」按顺序处理两边的全部队列。
  - PhotoCraft 不监视文件，不会像 Compositor 那样自动载入：追加或重算前先在 PhotoCraft 里 ⌘S，做完在 PhotoCraft 里按 F12（文件 › 恢复）载入。运行期间文档被 PhotoCraft 保存过时，脚本不写入，app 自动再跑一次。
  - **重算自动层**：在 PhotoCraft 里手修过下面的图层后（先 ⌘S），点卡片上文档旁的「重算」或预览上方的「重算自动层」：磨皮按现在的画面重算，骨相、眼神光、梦幻柔焦（在 PhotoCraft 里是"盖印的智能对象 + 智能滤镜"）重新盖印，不加新图层。
  - 「在 PhotoCraft 中打开」只在装了 PhotoCraft 时可用，只在点击时打开它。悬浮球是配合 Compositor 窗口用的，PhotoCraft 标签页不显示。
  - 各种图层在 PhotoCraft 里是什么、和 Compositor 有哪些不同，见 `photocraft-retouch/references/mapping.md`。

- **直接修 Compositor 里正在编辑的工程**：左上角的「Compositor」卡片会自动认出它，点「精修这个工程」就用右边的设置开始修；队列为空时，中间也会大幅显示这个工程。修完 Compositor 会自动载入新图层（它会监视工程文件）。脚本把这次的图层先写在包内的隐藏文件夹 `.retouch/`，最后几毫秒内一起放进去，Compositor 只重载一次；它每次重载都要重新解码工程里所有图层，所以图层越多、16 位层越多，这一下越久。
  - 认出当前工程：Compositor 的窗口不告诉系统工程文件在哪（AXDocument 是空的），只有标题，也就是工程名。所以 app 拿窗口标题去对两份名单：Compositor 进程此刻打开着的 .comp 包（内核的进程文件列表，不需要任何权限，不到一毫秒）和它最近打开过的工程；标题带「— 已编辑」之类的后缀、大小写不同也对得上。读窗口标题要一次「辅助功能」权限：卡片上点「允许读取」，在 系统设置 › 隐私与安全性 › 辅助功能 里打开「Compositor 工具」；它只用来读窗口标题，以及精修前替你按一下它的「存储」。没给权限时，Compositor 只开着一个工程的话也照样认出（卡片上会说明，并留着「允许读取」）；窗口标题对不上任何工程时，卡片会写出这个标题，建议在 Compositor 里 ⌘S 一次或重新打开它。签名带固定的指定要求（bundle id），所以装新版本后权限应该保留；不要手改装好的 app 里的 Info.plist（签名会失效，系统随即不认这份权限），要改就重新跑 `build.sh`；`build.sh` 还会在 `~/Library/Application Support/compositor-retouch/signing/` 准备一张本机自签证书，运行它打印的那条 `security add-trusted-cert` 命令信任一次后，以后就用证书签名。
  - 直接拖进 Compositor 的照片是「未命名」的新文档，磁盘上还没有工程文件，所以认不出来；在 Compositor 里按 ⌘S 存成 .comp 后就会出现。
  - 没有权限或 Compositor 没开时，卡片列出 Compositor 最近打开过的工程（macOS 的「最近使用」记录，和它的 File › Open Recent 是同一份），也能一键精修。
  - 精修前 app 会先替你在 Compositor 里保存（通过辅助功能按一下它的「存储」菜单，按快捷键 ⌘S 找，不分语言），然后按工程大小等它写完（大工程最多半分钟），所以修的是你屏幕上的样子，Compositor 也不会再问"载入磁盘版还是保留我的"。运行记录里会写明是保存了、没写盘，还是没能保存（这时请自己 ⌘S）。万一 Compositor 的保存在脚本运行中途才落地，脚本会发现工程变了、不覆盖它，app 自动再跑一次。卡片和悬浮面板上的开关可以关掉它。
  - 磨皮方式跟着工程走：切到一个已经磨过皮的工程，「自动蒙版 / 手动刷出」自动改成它用的那种，按钮下面会写明；你再改回去，它会提醒"再点会多加一层磨皮"。图层改名只要保留开头的 emoji（手动磨皮是 🔥✋），照样被认出来重做。
  - 图层按用途放进文件夹（高低频、皮肤、光影、五官、辉光），已有同类文件夹时放进原来的文件夹。再点一次精修不会堆第二套：中性灰、双曲线、骨相、颗粒、同一种调色、观察组已经有了就跳过，磨皮按这次的设置原地重做（蒙版保留），骨相、眼神光是实时调整层、已有就跳过，只有辉光会叠加。Compositor 忙着重载大工程、一时读不到它的窗口时，卡片和悬浮球保持上一次的状态，不会闪成「允许读取」。
  - Compositor 1.5、1.6 存的工程（16 位或 HDR 图层，1.6 的格式 21）也能修。16 位的照片（16 位 TIFF、PNG）新建工程时原图保留 16 位，这样的工程要 Compositor 1.5 以上才能打开。
  - **重算自动层**：在 Compositor 里手修过下面的图层（比如在高低频上修过）之后，先 ⌘S 保存，再点卡片或悬浮面板上的「重算自动层」（圆球的菜单里也有）。磨皮层（以及旧工程里的眼神光像素层）会按工程现在的样子重新计算，不加新图层，蒙版和不透明度保留；骨相、眼神光的实时调整层本来就跟着下面变。工程里有可重算的层时才出现这个按钮。
  - **DR5 磨皮**卡片（悬浮面板里也有方式和力度）：默认「手动刷出」，给磨皮层一个黑蒙版，像 PS 里 DR5 插件的手动磨皮一样，在 Compositor 里用白画笔刷哪里磨哪里；「自动蒙版」按识别出的皮肤范围盖上。以前存下的「自动蒙版」是当时的默认，升级后改成手动刷出，要自动就再点一次。
  - **PhotoCraft 联动**：PhotoCraft 标签页的卡片上有「联动启动 PhotoCraft」（PhotoCraft 没在运行时可用）。这样启动的 PhotoCraft 开着本机控制端口，允许自动化读写用户文件夹；之后在 PhotoCraft 里开着的文档，精修、重算前自动替你保存，做完自动关掉再打开（回到原来的标签位置），不用再按 ⌘S 和 F12。卡片每几秒看一次 PhotoCraft 是否在联动，连上了显示「已联动 PhotoCraft」。第一次用可以在终端运行 `photocraft-retouch/scripts/link_check.py` 实测一遍。
  - **高低频**卡片：半径「按脸宽」（脸宽的 1/200）或「手动」拖滑块（1.5–40 像素）。已有的高低频还没手修过时，换了半径再点精修会按新半径原地重做；手修过的（哪怕一笔）不动，要换就先删掉「🎚️ 高低频」文件夹。PhotoCraft 文档里已有的高低频不会重做。力度轻、中、重分别盖 53%、88%、100%，重也更积极地先祛痘；它和「辉光与调色强度」滑块互不影响。
  - **排队**：已经有图在修时点精修，这张会排进队列（按钮变成「加入队列」，下面写「前面还有 N 张」），你可以马上切到下一张接着加，修完一张自动接下一张。悬浮面板顶部列出整个队列，每张都有进度、✓ 或 ✗；圆球右下角的数字是还剩几张。
  - **切换图片时自动加入队列**（开关，默认关）：打开后，在 Compositor 里切到一张还没修过的图，它就自己排进队列。修过的图切回来不会再排，否则会叠第二组图层。
- **悬浮球**：工具栏或 Compositor 卡片上的「悬浮球」按钮，会把 app 缩成一个浮在所有窗口上面的小圆球（主窗口隐藏），专门配合 Compositor 用。
  - 圆球：右上角绿点表示认出了 Compositor 正在编辑的工程；处理时外圈是橙色进度环；完成后闪一下 ✓。拖动可以挪位置，位置会记住。
  - 点圆球：旁边弹出小面板，上面是当前工程，中间是预设、全部功能（点一下开或关）、调色、辉光和强度，底部是「精修这个工程」和进度。设置和完整窗口共用同一份。
  - 圆球和面板都不会抢走 Compositor 的焦点。右键圆球有「精修 / 选择功能 / 打开完整窗口 / 退出」。点 Dock 图标也能回到完整窗口。下次打开时，会恢复上次用的模式。
- **速度**：app 自带编译好的人脸识别组件和人像分割模型，第一次精修不用等现场编译（以前要 swiftc，二三十秒）和下载。PNG 图层在后台线程写，刚写的图层直接从内存读，合成时提前解码后面几层。Compositor 里开着的工程不渲染预览图（看 Compositor 就行），中间默认显示「总览」（修前修后、皮肤蒙版、五官预涂拼成的一张）。在这台 Mac 上，2400 万像素的工程（当时测的是旧版的全自动预设）从 15.9 秒降到 8.3 秒（不渲染）或 11.5 秒（渲染）。「运行记录」每行前面都有从开始算起的秒数，能看出时间花在哪一步。
- 第一次启动会显示欢迎页。点「开始准备」后，app 联网下载 NumPy、OpenCV、Pillow，以及可选的人像分割运行库 ai-edge-litert，装进 `~/Library/Application Support/RetouchStudio/venv`，不碰系统 Python。之后完全离线使用。
- 把照片（JPEG、PNG、TIFF、HEIC）或已有的 `.comp` 工程拖进窗口，也可以按 ⌘O 选择，或者拖到 Dock 图标上。
  - 照片会新建工程，默认放在照片旁边，名字是 `名称.comp`。重名时用 `名称 2.comp`，不会覆盖已有的工程。也可以统一放到一个选定的文件夹里。
  - 已有工程会追加图层。DR5、影棚两个预设在脚本里只用于从照片新建；用在已有工程上时，app 把它们的模块逐个传过去，效果一样。
- 在右边选预设（常用、DR5、影棚、自选）、模块（DR5 磨皮、高低频、中性灰、双曲线、观察组、3D 骨相、眼神光）、DR5 磨皮的方式（手动刷出、自动蒙版）、高低频的半径、力度（轻、中、重）和质感（自然、柔和、光滑；柔和接近 DR5 插件的细腻）、调色、辉光（原色、单色、双色）、颗粒、辉光与调色强度，然后点「开始精修」（⌘↩）。
  - 默认是「常用」：中性灰、DR5 磨皮、观察组，也就是中性灰调光影再磨一下皮。所有设置都会记住，下次打开 app 还是上次的样子。
  - 预设只是起点：点一个预设，会把它包含的开关都打开，之后每个开关都还能改（点整行也行）。改过以后，预设下面会写出「在『常用』基础上：+… −…」，旁边有「恢复预设」。
  - 交给脚本的仍然是这个预设，加上的模块按名字传，去掉的用 `--without`；磨皮总是带着方式传（`--delicious-skin manual` 或 `auto`），力度按 `--skin-strength` 传；有高低频时半径按 `--blur-radius auto` 或像素数传。DR5、影棚两个预设在脚本里只能用来新建工程，用在已有工程上时，app 改成把它们的模块逐个传过去。
  - 精修按钮下面有一行说明这次会做什么（比如「常用 · 3 项 · 自动蒙版 · 磨皮轻 · 胶片暖调」，默认的手动刷出不写），旁边的「调整」会打开右边的设置。
  - 队列里的照片一张接一张处理，左边每张都有进度环，显示当前步骤。
  - 某一张失败不影响后面的，失败原因用中文显示，完整记录在「运行记录」里。右键可以重新排队或移除。
  - 「停止」相当于 Ctrl-C：正在处理的那张会撤销写了一半的文件，不会留下坏工程。退出 app 时也一样。
- 中间显示效果（`--render` 合成的整幅预览）、原图和各张检查图（总览在最前）。装了 Compositor 时，「在 Compositor 中打开」会用它打开工程。这是唯一会打开其他 app 的操作，只在用户点击时发生。
- 设置（⌘,）里能看到运行环境状态、重新安装环境，以及 app 正在用哪份脚本。

app 运行的是 skill 文件夹里的 `scripts/retouch_builder.py`，这个路径编译时写进 Info.plist 的 `RetouchSkillScripts`，所以改了脚本立即生效。文件夹被移走时，改用打包进 app 的那份副本。

## 编译、测试

```bash
app/build.sh                 # 编译、签名（固定指定要求；有受信任的本机证书时用证书），打包成 skill 文件夹里的 Compositor 工具.dmg（不安装、不打开，访达里什么都不会出现）
app/build.sh <文件.dmg>      # 写到别的位置
app/Tests/run.sh             # 逻辑测试：参数拼接、命名、输出解析（离线，几秒）
app/Tests/run.sh e2e         # 再加端到端测试：像第一次启动那样，联网把环境装进临时文件夹，再真实跑几批
SUPPORT=<文件夹> app/Tests/run.sh e2e   # 复用之前装好的环境
app/Tools/snapshot.sh screens <输出文件夹> <照片文件夹> [<做好的工程文件夹>]   # 离屏渲染各个界面的截图
app/Tools/snapshot.sh icon   # 重新生成 Resources/AppIcon.icns
app/Tools/snapshot.sh dmg [预览.png]   # 重新生成安装窗口的背景 Resources/dmg-background.tiff，可选输出浅色、深色两种预览
```

安装窗口的布局（背景、图标位置、隐藏工具栏和侧栏）由 [dmgbuild](https://github.com/dmgbuild/dmgbuild) 直接写进磁盘映像的 `.DS_Store`。它用 `-nobrowse` 挂载，不需要像 create-dmg 那样打开访达窗口、跑 AppleScript。

- dmgbuild 第一次用时，会联网装进 `~/Library/Caches/compositor-retouch/dmgbuild`。
- 背景用的是中等亮度的渐变，因为访达写在上面的图标名字在浅色模式下是黑字、深色模式下是白字，两种都要看得清。
- 访达不会播放磁盘映像窗口里的动画，所以背景是静态的。

只要 Xcode 命令行工具里的 `swiftc`，不需要 Xcode 工程。测试和截图都不会打开任何窗口，也不会启动 app。

推送到 GitHub 后，`.github/workflows/ci.yml` 在 GitHub 的 macOS 26 机器上跑逻辑测试和 PhotoCraft 技能的测试；推送到 `main` 且测试都通过时，再构建 dmg、把技能文件夹（含 dmg）打成 `compositor-retouch-<日期>.zip`，以 `v<年.月.日>` 为版本号（同一天再发是 `.2`、`.3`）自动发布到 Releases。也可以在 Actions 页面手动运行它发一版。

端到端测试会检查以下几项：

- 安装的四个步骤；
- 一批照片：两张 JPEG、一张 HEIC 和一个坏文件；
- 每张都按顺序报告了步骤；
- 生成了工程、渲染图和检查图；
- 重名时会编号；
- 坏文件的失败原因；
- 给已有工程追加调色；
- DR5 用在工程上逐模块追加，去掉的模块不跑，手动刷出的磨皮层带黑蒙版；
- 重算只换像素、不加图层；
- 中途停止后不留下工程。

在 Homebrew Python 3.14 上，安装用了 14 秒（pip 有缓存），每张 1000 万像素的照片走 DR5 预设加中性灰、调色和辉光约 6 秒。

## 外观

中性的石墨灰色。选中的项目和主按钮用「墨色」，浅色模式下是黑色，深色模式下是白色。唯一的彩色是暗房安全灯那种橙色，只用在进度和需要注意的地方。界面里不用紫色渐变，也不用 ✨ 这类图标，让照片自己做主角。

- 图标是石墨色圆角方块，上面一个镜头光圈，加一个橙色的小安全灯。
- 安装窗口的背景是摄影用的 18% 中灰：访达写在背景上的图标名字，浅色模式下是黑字，深色模式下是白字，中灰上两种都看得清。

## 截图的限制

截图是在一个从不显示的窗口里画出来的，进程也不能成为前台应用。这样拍出来有几处和真实窗口不一样：

- Liquid Glass 由窗口服务器合成，离屏画不出来，所以截图模式（`snapshotMode`）里卡片改用半透明材质。
- `NavigationSplitView` 的玻璃侧栏和检查器会显示成空白或花屏。所以 `Columns` 把三栏分别画出来再拼在一起，用于检查。
- 窗口不是活动窗口，开关和选中行都显示成非活动时的灰色。

这些截图能用来检查排版、文字和配色，但最终效果要在真实窗口里看。

## 文件

| 文件 | 内容 |
|---|---|
| `Sources/Model.swift` | 预设、模块、调色、辉光、设置、队列中的一项 |
